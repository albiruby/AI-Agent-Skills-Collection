# Project and Business Profiles

Profiles help prioritize scenarios. A project may match multiple profiles. Do not infer that a feature exists merely because it is common in that profile.

## Marketing / landing page

Prioritize message clarity, CTA behavior, forms, accessibility, responsive layout, content accuracy, SEO, analytics, consent, performance, and lead-delivery reliability. Check that form submissions reach the intended destination and failures are visible.

## Portfolio / personal site

Prioritize content presentation, navigation, accessible media, project links, contact workflow, responsive layout, metadata, performance, and privacy. Do not spend time on nonexistent account or payment systems.

## Blog / publishing / documentation

Prioritize editorial lifecycle, content integrity, drafts and publication, author attribution, canonical URLs, redirects, search, navigation, code/media rendering, indexing, localization, and stale content.

## E-commerce

Prioritize product/catalog accuracy, prices/currency/tax policy, cart integrity, inventory races, promotions, checkout, payment state, webhook handling, refunds, order lifecycle, shipping, customer data, and post-purchase notifications. Treat payment testing as high-risk; use sandbox/test modes only with authorization.

## SaaS / subscription application

Prioritize tenant isolation, account lifecycle, onboarding, entitlements, billing, usage metering, quotas, plan changes, cancellation, access enforcement, data export/deletion, background jobs, audit trails, and operational visibility.

## Marketplace

Prioritize buyer/seller boundaries, listings, moderation, transaction lifecycle, commission calculations, payout controls, disputes, messaging, fraud/abuse, inventory or availability, and role conflicts.

## Booking / reservation / scheduling

Prioritize availability consistency, concurrent reservation, hold expiration, timezones, daylight-saving transitions, cancellation, rescheduling, no-show policies, capacity, notifications, and payment/refund interactions.

## Community / social platform

Prioritize content and account abuse, moderation, reporting, blocking, privacy settings, feed visibility, notification preferences, uploads, rate limits, search indexing, and deletion propagation.

## Dashboard / internal business tool

Prioritize role separation, data correctness, bulk operations, exports, destructive action safeguards, audit history, operational recovery, data freshness, and accessibility. Internal tools still require security and privacy controls.

## Learning platform

Prioritize enrollment, course access, progression, assessment integrity, grading, completion rules, content availability, certificates, payment/entitlement alignment, and learner data privacy.

## API-first / developer platform

Prioritize authentication, authorization, versioning, schema contracts, pagination, rate limits, idempotency, error consistency, documentation accuracy, SDK compatibility, observability, and abuse prevention.

## AI-enabled product

Prioritize input/data boundaries, prompt injection exposure, output validation, tool permissions, sensitive data disclosure, model/provider outages, latency, cost controls, rate limits, evaluations, human override, and graceful fallback. Treat model outputs as untrusted until validated.

## Static site / frontend-only app

Prioritize build and asset integrity, client-side data exposure, accessibility, responsive behavior, routing, forms and third-party services, SEO/indexability, performance, browser compatibility, and deployment configuration. Mark backend-specific checks Not Applicable only after confirming no such service exists.
